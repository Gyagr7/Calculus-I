    Section 4.1 Areas and Distances

    Today’s Question.

    Can we get the change in position directly from the velocity — without ever finding the position function?
    🔗
    🔗
    Remember our car? Velocity \(v(t) = 3t^2\) meters per second, starting at \(s(0) = 0\text{.}\) In Subsection 3.3.8 we worked backward: we found an antiderivative \(s(t) = t^3\text{,}\) and then \(s(2) - s(0) = 8\) meters.
    🔗
    That method needed a formula for \(s\text{.}\) Today we ask what happens if we only ever know the velocity, and never find \(s\) at all. For now, pretend we do not know the position function.
    🔗

    Subsection 4.1.1 Start with constant velocity

    Suppose a car travels at a constant \(20\) meters per second for \(3\) seconds. How far does it go?
    🔗

    Checkpoint 4.1.1. Easy case.

    🔗
    Now graph the velocity: a flat line at height \(20\text{,}\) from \(t = 0\) to \(t = 3\text{.}\) The region underneath it is a rectangle, with width \(3\) and height \(20\text{.}\) Its area is also \(60\text{.}\)
    🔗

    Fact 4.1.2. Distance is area.

    When velocity is constant, distance traveled equals the area under the velocity graph.
    🔗
    🔗
    Why does this happen? Check the units:
    \begin{equation*} \left(\frac{\text{meters}}{\text{second}}\right)(\text{seconds}) = \text{meters}. \end{equation*}
    Multiplying a rate by a length of time is exactly what finding the area of a rectangle does: height times width.
    🔗
    🔗

    Subsection 4.1.2 But our car does not move at a constant velocity

    Return to \(v(t) = 3t^2\text{.}\) The velocity changes every instant, so we cannot just multiply one velocity by \(2\) seconds.
    🔗
    What if we break the two seconds into smaller pieces, and pretend the velocity is constant on each small piece? You may recognize this table from your warm-up before class — dividing \(0 \le t \le 2\) into four equal pieces of width \(\Delta t = 0.5\) gives:
    🔗
    \(t\) \(0\) \(0.5\) \(1\) \(1.5\) \(2\)
    \(v(t) = 3t^2\) \(0\) \(0.75\) \(3\) \(6.75\) \(12\)
    Over a short interval, we can pretend the velocity is approximately constant. From \(t = 0.5\) to \(t = 1\text{,}\) the width is \(\Delta t = 0.5\text{.}\) Using the velocity at the start of the interval, \(v(0.5) = 0.75\text{,}\) the change in position is approximately
    \begin{equation*} \Delta s \approx v(0.5)\,\Delta t = (0.75)(0.5) = 0.375 \text{ meters}. \end{equation*}
    Geometrically, this is the area of one thin rectangle.
    🔗

    Fact 4.1.3. One rectangle, one small change.

    rectangle area \(=\) (velocity)(time) \(\approx\) change in position.
    🔗
    🔗
    🔗

    Subsection 4.1.3 Add the small changes together

    Use the velocity at the left endpoint of each of the four intervals \([0, 0.5]\text{,}\) \([0.5, 1]\text{,}\) \([1, 1.5]\text{,}\) \([1.5, 2]\text{.}\) This is called a left-endpoint sum, written \(L_4\text{:}\)
    \begin{equation*} L_4 = v(0)(0.5) + v(0.5)(0.5) + v(1)(0.5) + v(1.5)(0.5). \end{equation*}
    🔗

    Checkpoint 4.1.4. Compute L4.

    🔗
    Now do the same thing with right endpoints:
    \begin{equation*} R_4 = v(0.5)(0.5) + v(1)(0.5) + v(1.5)(0.5) + v(2)(0.5). \end{equation*}
    🔗

    Checkpoint 4.1.5. Compute R4.

    🔗
    So the true change in position is trapped:
    \begin{equation*} 5.25 \;\lt\; \text{change in position} \;\lt\; 11.25. \end{equation*}
    🔗

    There it is again.

    Remember the number 8 from our antiderivative work? It sits right between \(5.25\) and \(11.25\text{,}\) exactly where it should.
    🔗
    🔗
    Can we do better than \(L_4\) and \(R_4\text{?}\) One idea: use the midpoint of each interval instead of an endpoint.
    🔗

    Checkpoint 4.1.6. Compute M4.

    🔗
    Drag \(n\) below to use more rectangles, and toggle the endpoint. Watch what happens to the estimate as the rectangles get thinner.
    🔗

    Checkpoint 4.1.8. What did you notice?

    As \(n\) grows, what happens to the gap between \(L_n\) and \(R_n\text{?}\)
    🔗
    Solution.
    The gap shrinks toward \(0\text{,}\) and both \(L_n\) and \(R_n\) squeeze in on the same number: \(8\text{.}\)
    🔗
    🔗
    🔗
    🔗

    Subsection 4.1.4 The same idea, without any velocity at all

    Forget velocity for a moment. Suppose we want the area under \(f(x) = x^2\) from \(x = 0\) to \(x = 1\text{.}\) This region is not a rectangle, triangle, or circle, so there is no ready-made formula.
    🔗
    We do exactly what we just did: replace one hard region with many easy rectangles. Divide \([0, 1]\) into four equal pieces, so \(\Delta x = 0.25\text{.}\) Using left endpoints,
    \begin{equation*} L_4 = 0.25\left[0^2 + \left(\tfrac14\right)^2 + \left(\tfrac12\right)^2 + \left(\tfrac34\right)^2\right] = \tfrac{7}{32} = 0.21875. \end{equation*}
    Using right endpoints,
    \begin{equation*} R_4 = 0.25\left[\left(\tfrac14\right)^2 + \left(\tfrac12\right)^2 + \left(\tfrac34\right)^2 + 1^2\right] = \tfrac{15}{32} = 0.46875. \end{equation*}
    Since \(x^2\) is increasing on \([0,1]\text{,}\) \(L_4 < \text{actual area} < R_4\text{.}\)
    🔗
    Compare the two situations side by side:
    🔗
    Area problem Distance problem
    width \(= \Delta x\) time width \(= \Delta t\)
    height \(= f(x)\) height \(= v(t)\)
    \(f(x)\Delta x\text{:}\) small rectangle area \(v(t)\Delta t\text{:}\) small change in position
    add the rectangles add the changes in position

    The same rectangle sum, two different stories.

    The same rectangle sum can represent an area under a curve, or an accumulated physical quantity such as a distance travelled.
    🔗
    🔗
    🔗

    Subsection 4.1.5 The general rectangle recipe

    Suppose \(f\) is positive on \([a, b]\text{.}\) Break the interval into \(n\) equal pieces, each of width
    \begin{equation*} \Delta x = \frac{b - a}{n}. \end{equation*}
    Inside each small interval, choose one point \(x_i^*\text{.}\) One rectangle has area \(f(x_i^*)\,\Delta x\text{.}\) Adding all \(n\) rectangles gives
    \begin{equation*} f(x_1^*)\Delta x + f(x_2^*)\Delta x + \cdots + f(x_n^*)\Delta x. \end{equation*}
    🔗

    Definition 4.1.9. Riemann sum.

    A sum of the form
    \begin{equation*} \sum_{i=1}^{n} f(x_i^*)\,\Delta x \end{equation*}
    is called a Riemann sum for \(f\) on \([a, b]\text{.}\)
    🔗
    🔗
    What happens as we use more and more, thinner and thinner rectangles? As \(n \to \infty\text{,}\) we have \(\Delta x \to 0\text{,}\) and our approximation approaches the exact area:
    \begin{equation*} A = \lim_{n \to \infty} \sum_{i=1}^{n} f(x_i^*)\,\Delta x. \end{equation*}
    🔗

    Important idea.

    We do not build rectangles because rectangles are the goal. We build rectangles because their areas are easy to compute, and increasingly thin rectangles let us capture a curved region exactly.
    🔗
    🔗

    Remark 4.1.10. A note on notation.

    That limit expression is correct, but long. Next class we give it a much shorter name — and along with it, a symbol you may already have seen somewhere. We are saving it for Section 4.2 on purpose, so you see exactly where it comes from first.
    🔗
    🔗
    🔗

    Subsection 4.1.6 When all we have is a table

    A cyclist’s velocity is recorded every two seconds:
    🔗
    \(t\) (s) \(0\) \(2\) \(4\) \(6\) \(8\)
    \(v(t)\) (m/s) \(2\) \(4\) \(7\) \(9\) \(10\)
    We have no formula for \(v(t)\text{,}\) but we can still estimate the distance.
    🔗

    Checkpoint 4.1.11. Estimate from a table.

    🔗
    Now suppose oil leaks from a tank at a decreasing rate:
    🔗
    \(t\) (hours) \(0\) \(2\) \(4\) \(6\)
    \(r(t)\) (liters/hour) \(10\) \(8\) \(7\) \(5\)

    Checkpoint 4.1.12. A decreasing rate.

    🔗

    Fact 4.1.13. The unit test.

    One of the fastest ways to understand an accumulation problem is to multiply the units: rate \(\times\) small input change \(=\) small accumulated amount. This works whether the rate is \(\text{meters}/\text{second}\text{,}\) \(\text{liters}/\text{minute}\text{,}\) or \(\text{dollars}/\text{item}\text{.}\)
    🔗
    🔗
    🔗

    Subsection 4.1.7 Putting it together

    Checkpoint 4.1.14. You do: a right-endpoint estimate.

    Estimate the area under \(f(x) = x^2 + 1\) from \(x = 0\) to \(x = 2\) using four right-endpoint rectangles.
    🔗
    Solution.
    \(\Delta x = \tfrac{2 - 0}{4} = 0.5\text{,}\) with right endpoints \(0.5, 1, 1.5, 2\text{.}\)
    \begin{equation*} R_4 = 0.5\big[f(0.5) + f(1) + f(1.5) + f(2)\big] = 0.5(1.25 + 2 + 3.25 + 5) = 5.75. \end{equation*}
    Since \(f\) is increasing on \([0, 2]\text{,}\) this is an overestimate.
    🔗
    🔗
    🔗

    Checkpoint 4.1.15. Conceptual check.

    1. Why does a rectangle under a velocity graph represent a distance?
      🔗
      🔗
    2. What does making the rectangles thinner accomplish?
      🔗
      🔗
    3. For an increasing function, which gives the larger estimate: left endpoints or right endpoints?
      🔗
      🔗
    4. If a quantity changes at rate \(r(t)\text{,}\) what does \(r(t)\Delta t\) approximately represent? What does adding many such terms represent?
      🔗
      🔗
    🔗
    Solution.
    1. Multiplying velocity by a time width gives (rate)(time) \(=\) distance, which is exactly a rectangle’s area.
      🔗
      🔗
    2. Thinner rectangles hug the curve more closely, so the approximation gets more accurate.
      🔗
      🔗
    3. Right endpoints give the larger estimate, since the function’s largest value on each interval sits at the right edge.
      🔗
      🔗
    4. \(r(t)\Delta t\) approximates one small accumulated amount. Adding many of them approximates the total accumulated amount.
      🔗
      🔗
    🔗
    🔗
    🔗

    Checkpoint 4.1.16. Exit ticket.

    1. A car travels at \(30\) ft/s for \(4\) seconds. How far does it travel?
      🔗
      🔗
    2. A velocity graph is divided into rectangles of width \(0.2\) seconds. One rectangle has height \(15\) ft/s. What physical quantity does \((15)(0.2)\) represent?
      🔗
      🔗
    3. If a positive function is increasing, is a left-endpoint sum usually an underestimate or an overestimate?
      🔗
      🔗
    4. In your own words, why can rectangles help us find the area under a curve?
      🔗
      🔗
    🔗
    Solution.
    1. \(30 \cdot 4 = 120\) feet.
      🔗
      🔗
    2. \(3\) feet — the distance travelled during that \(0.2\)-second interval.
      🔗
      🔗
    3. An underestimate, since the left edge holds the smallest value on an increasing function.
      🔗
      🔗
    4. Because a curved region can be approximated as closely as we like by many thin rectangles, whose areas we already know how to compute.
      🔗
      🔗
    🔗
    🔗
    🔗

    Today’s main idea.

    A changing quantity can be accumulated by breaking time or space into small pieces, approximating each piece with a rectangle, and adding: rate \(\times\) small interval \(\approx\) small accumulated amount.
    🔗
    One method works backward from the rate, using an antiderivative. The other method adds up the rate, using increasingly thin rectangles. Soon we will discover why these two methods give exactly the same answer.
